# Manual de Convivencia y Flujo de Trabajo

## Objetivo

Definir las normas y lineamientos para la organización y colaboración del equipo durante el desarrollo del proyecto BottleCRM.

---

# Uso de GitHub

## Repositorio

Todo el trabajo del proyecto deberá gestionarse mediante GitHub utilizando:
- Issues
- Pull Requests
- GitHub Projects
- Branches

---

# Gestión de Issues

## Reglas generales

- Cada tarea debe registrarse como un Issue.
- Los títulos deben ser descriptivos.
- Todo Issue debe tener:
  - responsable,
  - descripción clara.

---

# Flujo Kanban

A partir del Sprint 1, el tablero GitHub Projects utilizará las siguientes columnas:

| Columna | Descripción |
|---|---|
| Backlog | Tareas pendientes |
| In Progress | Tareas en desarrollo |
| Review | Tareas en revisión |
| Done | Tareas finalizadas |

---

# Pull Requests

## Reglas

- Todo cambio importante debe realizarse mediante Pull Request.
- El Pull Request debe incluir:
  - descripción,
  - Issue relacionado,
  - cambios realizados.

---

# Normas Generales

- Mantener comunicación constante.
- Documentar cambios importantes.
- No subir credenciales ni archivos sensibles.
- Respetar la estructura del proyecto.
- Mantener código legible y modular.

---

# Sprint 0

Durante el Sprint 0 se trabajará en:
- Organización del proyecto.
- Configuración inicial.
- Documentación base.
- Preparación del entorno de desarrollo.

---

# Conclusión

Este manual busca mantener una organización clara del equipo y garantizar buenas prácticas de desarrollo colaborativo utilizando GitHub y metodologías ágiles.
